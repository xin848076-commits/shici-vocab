# 拾词 · WORD BY WORD

一个纯前端的英语单词学习网页。中文界面，无账号、无后端、无付费服务，词库和学习记录只存在你自己的浏览器里。

**在线试用**：https://xin848076-commits.github.io/shici-vocab/

> 打开时会看到 6 个示例词，不是词库缺失——**词库要从你自己收的词开始长**，这是设计如此。想快速看到完整效果，可以导入 `拾词备份-校正版-2026-11-08.json`（我自己的 125 词备份）。

> 当前状态：个人开发中，尚未完善。词库规模小、部分功能仍在打磨，详见下方「项目状态」与「Roadmap」。

## 项目状态

**这是一个进行中的个人项目，不是成品。**

- **词库由使用者自己收词**：今天读到什么词、学了什么词，就加什么词。不内置四六级预置词表，这是设计选择，不是没做完
- 我自己那份词库目前约 140 条，是日常积累的真实结果，不是"待扩充的数据缺口"
- A/B 级的边缘情况（生僻词、多词性混排、短语搭配）仍有处理不到位的地方
- 没有自动化测试套件，验证方式是 `tools/` 里的脚本 + 手动点击

我把它公开，是因为**它在真实使用中**（我自己每天用它背单词），而不是因为它已经完成。

---

## 它解决什么问题

这个项目有两个明确的差异点，都来自「我自己用着不顺手」的地方。

**第一，不做词表轰炸，只学自己收的词。**

常见背单词工具的默认姿势是：给你一张 3000 词的四六级表，从 abandon 开始。问题是——**表里的词不是你的词**。你今天在课文、阅读、真题里遇到的生词才是你真正需要的，而它们往往进不了任何一张词表。

拾词反过来：**词库从一开始是空的**，你遇到一个词，填进去，它才存在。所以：

- 没有「今日任务 50 个」的压力，只有「我今天收了 5 个词」
- 学的是自己的词，不是别人的词表
- 词库大小不构成评价标准，收进去的每个词都有出处

配套的本地词典（48,065 条常用及考试词汇、366,450 条短语）只用于**添加时查中文意思**，不参与学习排程——它不是词表，是抄写时的字典。

**第二，一个词按义项拆开，不只是记一条中文。**

四六级和考研词汇里大量是一词多义。比如 `bank` 既是「银行」也是「河岸」，`issue` 既是「议题」也是「发行」。只记第一条释义，结果是**单词认识，但句子读不懂**。

拾词的做法是：添加时从本地词典里勾选你实际要记的那几个意思，学习时按词义分别查看例句，每个义项各自配例句。

功能本身不受版权保护，但实现方式是独立写的。

## 功能

**学习流程**
- 翻卡回忆：先看英文 → 点卡片翻面看中文 → 选「还不会」或「记住了」
- 随机抽词（多个词时不会连续抽到同一个）、「只练不会的」重点复习
- 键盘操作：空格翻卡、右方向键抽词；输入框聚焦时不抢占按键

**每日目标与进度环**
- 可选每天记住 5 / 10 / 20 个**不同**单词，默认 10 个
- 只有点「记住了」才计入；同一词一天只计一次；达到目标有鼓励文字和一次性小动画
- 支持系统「减少动态效果」偏好

**单词成长花园**
- 每个词对应一盆植物，新词是种子
- 在不同日期记住三次 → 开花；点「还不会」→ 标记「需要浇水」，成长不清零
- 可按「需要浇水」「已开花」筛选，点植物直接跳去复习那个词

**添加单词时**
- 离线拼写检查：输入停顿约 0.3 秒，可疑拼写标红波浪线，给出候选词（Typo.js + SCOWL 词典，完全本地）
- 常见中文意思：本地词典可查 48,065 条常用及考试词汇、366,450 条短语，多选后一键追加到释义框
- 中英例句自动显示，也支持手写自定义例句

**发音**
- 点击卡片右上角 🔊 朗读，使用浏览器 Web Speech API，优先本地英语语音
- 发音不翻卡、不计复习次数、不自动播放

**数据管理**
- 全部数据存在浏览器 localStorage，自动保存
- 导出 / 导入 JSON 备份（含词库、掌握状态、每词复习次数、每日进度）
- 导入前显示条数确认，替换前提示先导出

**单词本**
- 搜索英文或中文、按状态筛选、点标签直接学习该词、按词义查看和编辑例句

## 技术实现

纯 HTML + CSS + 原生 JavaScript，**没有框架、没有构建步骤、没有 npm 依赖**。双击 `index.html` 就能跑。

| 模块 | 文件 | 职责 |
|---|---|---|
| 页面结构 | `index.html`（109 行） | 语义化结构 + ARIA 属性 |
| 样式 | `vocab.css`（约 50 KB） | 布局、卡片翻转、进度环、花园动画 |
| 主逻辑 | `vocab.js`（599 行） | 词库增删、抽词、翻卡、目标进度、导入导出 |
| 分义释义 | `vocab-meanings.js` | 多义项展示与勾选 |
| 例句 | `vocab-examples*.js`、`vocab-study-examples.js` | 本地例句匹配 + 网络词典兜底 |
| 拼写检查 | `vocab-spell.js` | 离线拼写建议 |
| 发音 | `vocab-speech.js` | SpeechSynthesis 封装 |
| 花园与激励 | `vocab-motivation.js` | 成长阶段、筛选、鼓励文案 |

几个实现上的选择：

- **不用框架**：目标是「双击就能用」的本地网页，加构建步骤会让使用者多一道门槛
- **不用 AI 接口**：拼写和释义全部本地数据，零成本、可离线、无隐私外发
- **例句分两级**：本地例句库优先（364 词 / 601 组，按词义匹配），未收录的才请求 Free Dictionary API，只发送英文单词本身
- **数据只在本地**：没有后端，所以不存在「你的生词被上传」

## 本地运行

```
双击 index.html
```

建议用 Edge / Chrome 打开。不需要安装任何东西，不需要命令行，不需要服务器。

**重要**：`index.html`、`vocab.css`、9 个 `vocab*.js` 必须和 `vocab-spell/`、`vocab-meanings/` 两个文件夹保持相对位置，缺一个就会白屏。

如果换电脑或移动文件夹：先在原位置「导出备份」，到新位置后再「导入备份」。localStorage 是按浏览器 + 文件位置隔离的，不会自动跟着走。

├── index.html                主页面

├── vocab-speech.js           发音

├── vocab-meanings/           ECDICT 词典数据（含许可证与来源）
├── tools/                    词库生成与检查脚本（Python / Node）
├── *说明-2026-*.md           各功能的设计与迭代记录

`tools/` 里的脚本用于处理词库数据：

- `prepare-vocab-meanings.py` / `prepare-vocab-spell.py` — 从上游数据源生成词典 js
- `audit-vocabulary.py` — 词库一致性核对
- `*-browser-cases.cjs` — 浏览器端功能用例（拼写、释义、例句、发音、花园）

## 开发方式说明

这个项目的开发过程是**需求由我提出、代码由 AI 编码工具（Codex）辅助生成、我再逐轮验收和调整**。

具体分工：

- **我的工作**：需求定义、功能设计、交互流程、文案、词库数据整理与核对、用例设计、逐轮测试与问题定位
- **AI 的工作**：把需求写成具体代码
- **仍在补的短板**：独立读懂全部代码、从零手写同等复杂度的模块

写这一段是因为：`git log` 里能看到真实的迭代过程，藏起来反而奇怪。
